### 2.2. Тип общих рёбер (швов):
- Ребро между плоской полкой `f[0]` и `f[1]`: `curve_type = GeomAbs_Line` (прямая линия).
- Ребро между `f[1]` и соседней плоской полкой `f[7]`: `curve_type = GeomAbs_BSplineCurve`!

### 2.3. Где проходит этот шов:
Шов проходит **строго на боковом торцевом срезе сектора гиба** (боковая заглушка цилиндрического сектора деформации):
- Сектор гиба генерируется через библиотечный вызов `SheetMetalBendSolid.bend_solid(...)`.
- Внутри `SheetMetalBendSolid.py` (строки 241–243) твёрдое тело сектора строится через OpenCASCADE BRepOffset:
  ```python
  bent_solid = OuterFace.makeOffsetShape(thickness, 0.0, fill=True)
  ```
- При офсете цилиндрической поверхности `BRepOffsetAPI_MakeOffsetShape` генерирует боковые торцевые грани сектора гиба не аналитическими плоскостями (`Geom_Plane`), а поверхностями типа **`Geom_BSplineSurface`**, ограниченными рёбрами **`Geom_BSplineCurve`**!

## 3. Шаг 4. Анализ гипотез H1, H2, H3

### Гипотеза H1: BSpline-геометрия препятствует UnifySameDomain
**ПОДТВЕРЖДЕНА (PRIMARY CAUSE)**.
- В OpenCASCADE `ShapeUpgrade_UnifySameDomain` оперирует аналитическими поверхностями (`Geom_Plane`, `Geom_Cylinder`, `Geom_Cone`). Когда смежная грань сектора гиба имеет тип `Geom_BSplineSurface`, даже если она геометрически компланарна плоскости полки с точностью $10^{-12}$, `UnifySameDomain` не объединяет её с `Geom_Plane`, поскольку их аналитические типы поверхностей не совпадают.
- В тех случаях, где зеркальное отражение `mirror(...)` в `fold_step` не затрагивало форму боковых рёбер или угол был $90^\circ$ с определённой ориентацией смещения, OpenCASCADE иногда удавалось конвертировать сектор в плоскость, но при знакомпеременных гибах (`z_10_20_10_ok`, `135_ok`) боковые грани сектора сохраняют тип `Geom_BSplineSurface`.

### Гипотеза H2: Соседние грани не компланарны
**ОПРОВЕРГНУТА**.
- Нормали всех смежных граней строго параллельны (на торцах $X=100.5$ и $X=0.5$ координата $X$ постоянна с погрешностью $< 10^{-14}$). BBox толщины по $X$ равен строго нулю.

### Гипотеза H3: UnifySameDomain не вызывается или нужен промежуточный вызов
**ОПРОВЕРГНУТА**.
- Эксперимент с вызовом `ShapeUpgrade_UnifySameDomain` после каждого промежуточного шага `fold_step` и повторный вызов на итоговом теле `restored.brep` дают абсолютно идентичный результат: 18 граней. Промежуточные вызовы не устраняют BSpline-геометрию, порождённую `makeOffsetShape`.

## 4. Предложение решения (без реализации, для будущих задач)

Для устранения остаточных швов на боковых срезах гибов в будущих версиях:
1. **Канонизация торцов сектора гиба в `SheetMetalFolder`**:
   - При создании сектора гиба заменять боковые грани типа `Geom_BSplineSurface` на аналитические плоские грани `Geom_Plane` с прямолинейными/круговыми кромками перед объединением `fuse`.
2. **Либо конвертация поверхностей**:
   - Вызов `ShapeCustom::ConvertToAnalytical` или реконструкция боковых заглушек сектора через `BRepBuilderAPI_MakeFace(wire, True)`.
