# Готовый промпт для Google Antigravity или другого AI-агента

Ты подключён к локальному репозиторию и установленному FreeCAD пользователя. Работай только в проекте Badsmc/SMBS_BendSeq, в ветке **development/performance-optimization**. Цель — существенно ускорить ручную native 3D-проверку OCC и автоматический поиск последовательностей гибки, не нарушив правильность диагностики коллизий.

## Обязательное чтение перед любыми действиями

1. Корневой `AGENTS.md`.
2. `docs/PERFORMANCE_OPTIMIZATION_MASTER_PLAN.md`.
3. `docs/PERFORMANCE_AGENT_HANDOFF.md` — особенно актуальная таблица статусов и последнее обновление.
4. `docs/PERFORMANCE_BENCHMARK_PROTOCOL.md`.

Эти файлы являются спецификацией и передаются вместе с проектом. Никаких собственных догадок о уже завершённых этапах. Перед работой выполни `git status`, `git branch --show-current`, `git rev-parse HEAD`, `git fetch` и проверь актуальность удалённой ветки. Не перезаписывай локальные изменения или исходную FCStd-деталь. Если git-дерево грязное, сохрани сведения о причинах, не делай разрушительных reset/clean.

## Непосредственная задача — Phase A3 (реальный замер)

Не запускай пока глобальный рефакторинг, многопроцессность и GPU. В Phase A1/A2 уже добавлены парсер журнала, метрики OCC и headless-тесты. **Кроме того, в этой же ветке уже реализованы и протестированы headless оптимизации: единый OCC Common для Conditional, безопасный AABB-отсев, кэш неизменных зон гибов и ограниченный LRU полных CAD-тел. Не реализуй их повторно и не заявляй о доказанном ускорении до сравнительного прогона в настоящем FreeCAD.** Теперь нужны фактические измерения и проверка правильности на компьютере пользователя. Исторические данные: `docs/PERFORMANCE_HISTORICAL_LOG6_BASELINE.md`.

1. Проверь, что FreeCAD реально загрузил именно новую ветку из одного `Mod` каталога; по событию `SMBS_RUNTIME_READY` проверь `module_file`. Старые дубли SMBS могут загружаться вместо нужной версии. Не удаляй чужие папки автоматически.
2. Открой реальную `2-1-3-4-(ok).FCStd` с десятью гибами и выбранную оснастку AP1017 / AT3015 V12; используй ту же последовательность B07 B03 B05 B01 B08 B04 B09 B10 B06 B02, ориентацию 180°, те же настройки виртуальной длины и Conditional 10 мм, если они были включены. Зафиксируй входные SHA-256, версии FreeCAD/OCC/Python, CPU и RAM, все параметры AdaptiveSamplingConfig и режим проверки.
3. Запусти именно **«Проверить 3D»**, не «Проверить 2D». Не считай первые четыре успешно проверенные гиба доказательством полной безопасной последовательности. Подсчитывай реальное время и статусы, фиксируй COLLSION/CONDITIONAL/UNVERIFIED честно.
4. Используй Desktop `SMBS_debug_log.json`. Он должен содержать события `MANUAL_NATIVE_CHECK_STARTED`, `PERF_NATIVE_BEND_KERNEL`, `MANUAL_NATIVE_BEND_TRAJECTORY`, `MANUAL_NATIVE_BEND_RESULT`, `MANUAL_NATIVE_CHECK_FINISHED`; часть последних может отсутствовать при отмене/аварии — это должно быть видно.
5. Для получения отчёта выполни из корня репозитория:
   
       python -m smbs_core.kinematics2d.performance_report "<полный путь>/SMBS_debug_log.json" --json --output "<полный путь>/SMBS_perf_baseline.json"

   Не изменяй исходный журнал. В отчёте проверь и запиши wall-time по гибам и фазам, количество и время `Part.common`, `distToShape`, перестроения полной детали, кэш, число выборок и точки коллизий.
6. Если запуск очень долгий, начни с одного полного прогона до фактической остановки (не обещай закончить за определённое время). При возможности повтори 3 cold + 3 warm прогона; укажи реальные объёмы выборок. Заполни таблицу по этапам и выдели узкое место на основании измерений.
7. Проверь, что `python -m unittest discover -s tests -p 'test_performance_report.py' -v` и остальные релевантные тесты зелёные. На Linux CI эти тесты не заменяют FreeCAD CAD-проверку.

## Следующий шаг — только после реального отчёта

Проверь эквивалентность уже внесённых Phase B/C оптимизаций; после замеров предложи **один следующий** минимальный эксперимент по самому дорогому оставшемуся месту (например, `multiFuse` или кросс-кандидатный кэш). Повторный Common при Conditional уже устранён и не является новым заданием. Сначала тест на эквивалентность, затем реализация и совпадающие результаты. Никакого ослабления допусков и превращения UNVERIFIED в PASS. Если в ходе проверки найден реальный баг — исправляй в рамках принятого контракта, с тестом, но не скрывай его.

В конце текущей работы обнови `docs/PERFORMANCE_AGENT_HANDOFF.md` (точный SHA, изменённые пути, команды тестов, FreeCAD-runtime, результаты и ограничения, следующая задача) и отправь изменения только в `development/performance-optimization` или в короткую дочернюю ветку с PR на неё. Не сливай в `main` или `smbs` без отдельного решения.

**Критически важно:** реальная цель — сделать исходный аддон быстрее и стабильнее. Ни одна оптимизация не должна ухудшать проверку физических столкновений, симуляцию, GUI или сохранение диагностики.
