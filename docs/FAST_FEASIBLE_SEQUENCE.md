# SMBS — экспериментальный быстрый поиск физически проверенного порядка

Ветка: `experiment/fast-feasible-sequence` (база: `development/coin3d-animation`).

## Назначение

Цель — найти **полный порядок гибов**, для которого существующий D6
подтверждает отсутствие столкновений **выбранных реальных FCStd пуансона и
матрицы** на проверенных участках траектории. Экспериментальный целевой
бюджет: 60 секунд. Данный режим **не является допуском для производства**:
задний упор, зажимы, корпус станка, перекладки, непрерывная коллизия между
дискретными состояниями и корректность операторской установки остаются
непроверенными. Данный инструмент не заявляет физическую возможность
всей станочной операции при отсутствии полного геометрического покрытия.

**Не путать три результата:**

1. `SAMPLED_2D_CLEAR_OR_TOUCH`: только быстрые 2D-сечения. Может не
   обнаружить 3D-столкновение. 2D-ошибка не всегда доказывает реальную 3D
   невозможность из-за другой установки и ориентации.
2. `SAMPLED_3D_TOOL_CLEAR_MACHINE_UNVERIFIED`: **все гибы** прошли
   независимую выборочную D6 проверку *реальной FCStd оснасткой*, включая
   RETRACT и проверенные положения пуансон–матрица. Это хороший кандидат
   для дальнейшей квалификации станка, **не** полное доказательство
   отсутствия столкновений на всём непрерывном пути.
3. `TIME_BUDGET_REACHED_UNVERIFIED`, `NATIVE_CANDIDATES_REJECTED_OR_UNVERIFIED`,
   `NO_2D_CANDIDATES_NOT_PROOF_OF_IMPOSSIBILITY`: корректный ответ «не
   удалось подтвердить», а не «изготовление невозможно».

## Архитектура — только уже существующие геометрические источники

### A. Быстрая приоритизация

`smbs_core/kinematics2d/sequence_search_2d.search_bend_sequences_2d`:
до 8 полных кандидатов, дешёвые 2D проверки, различные ориентации детали,
первоначальные короткие пробы корневых гибов, перебор и сортировка по весам.
При 60-секундном общем бюджете обычно резервируется 15 секунд на этот
этап, остальное — для D6.

Если начальный операторский порядок с полной картой ориентаций не
оказался среди 2D кандидатов, он может быть добавлен как **непроверенный
seed** для настоящей 3D проверки. Неполные порядки и отсутствующие
ориентации никогда не отправляются на принятие.

### B. Независимая проверка D6

`smbs_core/kinematics2d/manual_physical_validation.check_manual_3d_sequence`:
для каждого кандидата строится независимый FoldState. Оснастка берётся
из настоящих FCStd источников, виртуальная длина запрещена. Полная
адаптивная выборочная траектория должна подтвердить каждый гиб, включая
проверку пары инструментов и отвод пуансона. Ускорения:

- разделяемый внутри **одного запуска поиска** кэш неизменяемых OCC BRep
  листовых элементов; меняющаяся геометрия инвалидируется по сигнатуре;
- при ранней коллизии **не запускается дополнительная атрибуция
  поверхности** (до 30 секунд на выяснение какого именно компонента
  коснулись) — результат проверки столкновения остаётся реальным;
- reject-only фильтр компонентов разрешён, но **никогда не делает
  результат CLEAR** без полноценной D6 проверки;
- перед каждым следующим гибом проверяется бюджет поиска; ограничивается
  `max_phase_time_s`, а интервалы без достаточной проверки остаются
  UNVERIFIED.

Кэшируются **только геометрические объекты**, не вердикты об
отсутствии столкновений. Каждая комбинация порядка/ориентаций требует
собственной независимой проверки.

### C. Изолированное применение результата

В FreeCAD Tasks → «Поиск 2D вариантов»:
**«Пробный поиск + 3D (бюджет 60 с)»**.

После успешной полной выборочной проверки реальной оснасткой SMBS
переносит порядок и варианты разворота в текущую симуляцию, нумерует
линии на развёртке, сохраняет последовательность в списке для FCStd,
показывает результаты D6 по каждому гибу.

При TIMEOUT, COLLLISION, UNVERIFIED, неподходящих инструментах,
внутренней ошибке или изменении исходной детали во время поиска
**порядок не заменяется**, несмотря на найденные 2D варианты.
Диагностика записывается в Desktop `SMBS_debug_log.json` событием
`FAST_FEASIBLE_SEARCH_FINISHED` (или `FAST_FEASIBLE_SEARCH_ERROR`).

## Лимит 60 секунд — мягкий

Вызовы OpenCASCADE внутри одного состояния могут исполняться дольше
обозначенного предела. Прервать их из Python безопасно нет возможности,
поэтому время **не гарантировано**. Ограничения по фазам могут сделать
проверку UNVERIFIED; ослаблять допуски или объявлять это успешным
результатом нельзя. На сложном 10–20-гибовом изделии строгая проверка
может занимать больше минуты. Обязательное измерение на реальной
модели до оптимизаций/переноса ветки в `smbs`.

## Как проверять

1. Запустить исходную модель SheetMetal с 8–20 гибами, реальные пуансон и
   матрицу из FCStd, **отключить виртуальную длину**.
2. Нажать новую кнопку, записать время, статусы, полный порядок и
   карту ориентаций. Если результатов нет, сохранить лог — это не
   доказательство невозможности.
3. Если результат `SAMPLED_3D_TOOL_CLEAR_MACHINE_UNVERIFIED`:
   проверить весь список гибов/углов, визуально выполнить Play и вручную
   подтвердить достижимость заднего упора/корпуса/креплений, реальную
   последовательность перекладок и интервалов.
4. Изменить инструмент, угол или порядок и повторить — предыдущие
   диагностические CLEAR нельзя автоматически считать актуальными.
5. Прогнать на Windows и macOS FreeCAD 1.1 и проверить, что ни одна
   2D-кандидатура не выдаётся за физически подтверждённую.
6. Проверить 3D коллизию: обнаруженный блокер должен отклонять кандидата
   и запускать следующий, не принимая неполный результат.
7. По журналу разделить время между 2D, D6 и дополнительными OCC
   операциями; сравнивать одинаковые детали/оснастку/бюджет.

## Следующие физические блокеры

Для **действительно пригодного производственного порядка** потребуются:
модель пальцев упора и его переустановка, непрерывные перемещения,
ограничения корпуса станка, креплений, сегментов пуансона и матрицы,
проверка доступности поворотов и захвата детали, финальный независимый
прогон без искусственного ограничения на 60 секунд. В эту итерацию
не внесены обманные PASS, отключение проверок OCC или мёртвый
дублированный валидатор.

## Исправлено: верхняя кнопка запускает старый 2D-поиск (2026-11-16)

До исправления `PlanarCandidatesCommand.Activated` делал две вещи:
`show_workspace_controls(workspace, 3)` и затем немедленно
`workspace.calculate_planar_candidates()`. Это запускало старый
30-секундный DFS, скрывая основную кнопку нового FAST_FEASIBLE_SEARCH
за результатами/диалогом. Поэтому оператор не мог явно выбрать нужный
режим перед началом расчёта.

Теперь верхняя команда **«Поиск последовательности»** только открывает
раздел Tasks → «Поиск последовательности». Два отдельных действия:

- **«Поиск + 3D-проверка (60 с)»** — основной экспериментальный конвейер.
  После нажатия записывает `FAST_FEASIBLE_SEARCH_REQUESTED`, затем
  `FAST_FEASIBLE_SEARCH_FINISHED` либо отказ с причиной.
- **«Только 2D — без проверки (30 с)»** — явный отдельный просмотр,
  записывает `PLANAR_2D_ONLY_SEARCH_REQUESTED`. Никакая 2D-гипотеза
  не становится 3D-допуском.

Во время расчёта оба действия заблокированы, повторный поиск не запускается
вложенными Qt-событиями. Невозможность запустить FAST (нет инструмента,
включена виртуальная длина, запущен Play, уже идёт поиск) отображается в
поле Tasks, и пишется `FAST_FEASIBLE_SEARCH_PRECHECK_REJECTED`.

Важная проверка установленной версии: **в верхней панели должно быть
«Поиск последовательности», а не «Поиск 2D вариантов»**.
Если старое название всё ещё видно, FreeCAD, вероятно, загрузил старую
копию аддона. В Mod должна оставаться ровно одна активная копия SMBS;
другие `SMBS_BendSeq*` временно переместить за пределы каталога Mod
и полностью перезапустить FreeCAD.

Headless-тест `tests/test_search_command_routing.py` выполняет реальный
метод `Activated` в изолированном окружении и явно запрещает вызовы обоих
поисков из верхней кнопки. Не заменяет проверку встроенного Qt в FreeCAD.
