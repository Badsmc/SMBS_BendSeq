# Инцидент при настройке предгибов — 2026-11-20

Источник: `SMBS_debug_log(20261120-063955).json`, журнал 852 событий.
Верстак FreeCAD 1.1, Windows / PySide6 Qt 6.8.3.

## Наблюдения, а не предположения

- Зафиксированы два процесса FreeCAD, настройка предгибов и
  перетаскивание строк `B02.1`, `B04.1`, `B02.2`, `B04.2`.
- До закрытия последнего процесса зарегистрирована корректная операция
  `STAGED_BEND_STEPS_REORDERED`; после неё — кадры предпросмотра.
- **Нет Python Traceback или UNHANDLED_PYTHON_EXCEPTION.**
- Оба процесса регистрируют `DOCUMENT_DELETED` и `QT_APPLICATION_QUIT`.
  Это события штатного закрытия Qt; файл **не подтверждает** конкретный
  native segfault или причину выхода приложения.
- У установленного аддона `git_branch=UNKNOWN`,
  `git_commit=UNKNOWN`. Поэтому SHA256 файлов в логе необходимо
  сопоставлять с реально запущенной установкой перед выводами о регрессии.

## Предположение, требующее проверки на Windows

После `QTreeWidget` InternalMove исходный код мог получать
`rowsMoved` во время native `dropEvent` и одновременно инициировать
перестройку строк и вложенных `QToolButton`. Повторная сигнализация или
вложенные Qt event loops могли создавать риск обращения к уничтоженному
C++-объекту. Лог не доказывает, что это вызвало закрытие FreeCAD.

## Защитные изменения

- Обработка переноса только от успешного окончания `dropEvent`,
  без параллельной подписки на `rowsMoved`.
- Во время native move блокируются смена активного этапа и
  перерисовка его `QTreeWidget`-ячеек.
- Единичный commit перестановки через 50 мс после drop event;
  флаги предотвращают повторную постановку задачи.
- Отказ от перестановки при запущенной симуляции или закрытии окна.
- Проверка полного набора operation IDs до изменения контроллера.
- Точки `STAGED_DROP_BEGIN`, `STAGED_DROP_COMMIT_STARTED`,
  `STAGED_DROP_REJECTED`, `STAGED_BEND_STEPS_REORDERED` в журнале.
- `faulthandler`, если ещё не установлен FreeCAD, пишет нативные
  Python stack traces в `SMBS_native_crash.log` на рабочем столе.
  Если FreeCAD уже установил свой обработчик, он не заменяется.

## Проверка пользователем

1. Убедиться, что установлена **новая** `manualmod.ui`.
2. Открыть тестовый FCStd, задать два предгиба и несколько раз менять
   порядок строк мышью. Добавлять/удалять предгиб, менять 180°.
3. Проверить: переносы не вызывают вылета, корректно сохраняются
   в Ctrl+S, восстановление FCStd возвращает ту же последовательность.
4. Если закрытие повторяется: сохранить `SMBS_debug_log.json`,
   `SMBS_native_crash.log` (если создан),
   и **Журнал надёжности Windows** (`perfmon /rel`) → FreeCAD →
   технические сведения об ошибке, особенно «Имя сбойного модуля»
   и код исключения. Не заменять отсутствующий crash stack догадкой.
5. Если в логе есть `QT_APPLICATION_QUIT`, проверить, не было ли
   штатного закрытия программы или завершения по команде UI.

Headless тесты покрывают контракт drag/drop и корректность порядка,
но не заменяют тест настоящего Qt event loop в FreeCAD на Windows.
