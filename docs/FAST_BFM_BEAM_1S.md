# Эксперимент FAST: BFM + bitmask + Beam Search (лимит 1 секунда)

Ветка: `experiment/fast-bfm-beam-1s` от `manualmod.ui`.
Это эксперимент с **быстрым поиском кандидатов**, не новый сертифицированный
поисковик технологических последовательностей.

## Как запустить

1. Установить **эту экспериментальную ветку** вместо текущего аддона и
   перезапустить FreeCAD 1.1.x.
2. Открыть FCStd, загрузить развёртку SheetMetal либо DXF в SMBS.
3. При необходимости добавить предгибы и указать вручную развороты 180°.
4. Остановить симуляцию и нажать Reset.
5. Открыть «Ручной порядок гибов» → **FAST — найти варианты (1 с)**.
   Никакого автоматического запуска при открытии вкладки нет.
6. Программа предложит до 5 последовательностей с приблизительной
   стоимостью. Выбор оператора применяет один вариант в ручной симуляции.
   Далее можно запускать обычный 3D просмотр и **отдельную** проверку OCC.
7. Сохранить стандартной кнопкой FreeCAD Ctrl+S. Применённый вариант и
   независимые повороты операций будут записаны в сессию SMBS внутри FCStd.

Нулевой результат означает только отсутствие кандидатов **в условиях
заданного времени и модели**. Не означает, что деталь нельзя согнуть.

## Что действительно проверяется

- Геометрия и этапы берутся из текущих `FoldState` и
  `StagedBendSequenceController` без изменения исходной детали.
- **BFM** в первой версии содержит достоверные зависимости:
  `B03.1` должен предшествовать `B03.2`. Можно передать дополнительно
  *проверенные* ограничения порядка или запрещённые переходы.
- Для реально выбранных пуансона и матрицы запускается существующий
  лёгкий **Stage A** один раз на физический гиб: наличие инструментов,
  корректность зоны и достаточность рабочей длины при отключённой
  виртуальной длине. Эти проверки статичны для данного гиба.
- Далее алгоритм хранит выполненные операции одним **битовым состоянием**,
  кэширует результаты одного и того же состояния и последней ориентации,
  использует ограниченный **Beam Search (32 состояния)**.
- При переборе неизвестных ориентаций создаются варианты 0°/180°.
  Явно выставленные пользователем галочки не изменяются поиском.
- Предварительный рейтинг учитывает группировку осей, изменение длины
  линии гиба, смену ориентации 0°/180°. Это **приближённая** стоимость
  для сортировки, **не** рассчитанный реальный поворот пресса.
- Граничный таймер измеряет **сам поисковый цикл**. Время открытия
  FreeCAD, подготовки SheetMetal, выбора инструмента, диалога и
  отрисовки не входит в 1 секунду.

## Что НЕ проверяется — принципиальная граница прототипа

- Stage B динамические сечения/траектории с коллизиями пуансона и
  матрицы **ещё не встроены в секундный цикл**: нынешние реализации
  могут работать дольше 1 секунды для одной детали.
- Отсутствие коллизий на протяжении APPROACH, BENDING, BOTTOM, RETRACT,
  TRANSFER, заднего упора, лапок, торцов инструментов, рам пресса,
  межоперационного поворота/перехвата и удержания заготовки.
- 3D непрерывная геометрия, усилие пресса, пружинение, устойчивость детали.
- Постоянное запоминание всех 5 кандидатов: сейчас в FCStd сохраняется
  только **применённый оператором** порядок через стандартный механизм.

Таким образом, **все** кандидаты имеют только статус
`UNVERIFIED_FAST_TOPOLOGY`. Их нельзя автоматически превращать в PASS.
Ошибка/пропуск Stage A или нехватка 1 секунды не являются доказательством
невозможности гибки.

## Испытания и метрики

```bash
python -m unittest discover -s tests -v
python tools/run_fast_bfm_beam_benchmark.py
```

Тесты используют синтетические графы с 8, 10, 15 гибами, включая два
отложенных догиба. Сравниваются длительность **поискового цикла**,
количество развернутых состояний, возвращённые варианты и выполненные
зависимости. Для реального утверждения о скорости необходимы замеры
пользователя в FreeCAD на `Omega.FCStd` и
`demo/parts/2-1-3-4-(ok).FCStd`; отдельно записывать время
подготовки исходной развёртки и выполнение проверки OCC.

После экспериментального этапа: добавить настоящую дешевую динамическую
2D коллизию по одному-двум сечениям, сначала получить измерения Stage B
на реальных деталях; если она сама превышает лимит, выполняйте её
**после** поиска над топ-K кандидатами, без ложной маркировки.
