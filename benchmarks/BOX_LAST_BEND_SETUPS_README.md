# Физическое исследование альтернативных постановок и оснастки для последних гибов коробки

Экспериментальное исследование в отдельной ветке `experiment/box-last-bend-setups` на базе коммита `9ab0c6b` (базовый замер сохранён в `benchmark/forward-backward-box-baseline`).

---

## 1. Среда, модель и воспроизведение

- **Модель**: `box.100out-50in-(ok).FCStd` (8 гибов: B01..B08)
- **Среда**: macOS (Darwin 24.3.0), FreeCAD 1.1.3 (build 39257), OCCT 7.8.1, Python 3.11
- **Базовый замер**: Все 8 кандидатов на последний гиб в закрытом состоянии коробки ($S = \{B01..B08\}$) отклонены физическим солвером из-за геометрических столкновений с прямой оснасткой `PUNCH_AP_1017` + `T-DIE_AT_3015`.

### Команды воспроизведения

```bash
# Воспроизведение 8 базовых блокирующих поз и генерация диагностических сцен (.FCStd)
PYTHONPATH="/Users/badmc/Library/Application Support/FreeCAD/v1-1/Mod:/Applications/FreeCAD.app/Contents/Resources/lib:." \
/Applications/FreeCAD.app/Contents/Resources/bin/python tools/reproduce_box_last_bend_collisions.py

# Сквозной запуск анализа альтернативных постановок, сдвигов и инструмента AP1013
PYTHONPATH="/Users/badmc/Library/Application Support/FreeCAD/v1-1/Mod:/Applications/FreeCAD.app/Contents/Resources/lib:." \
/Applications/FreeCAD.app/Contents/Resources/bin/python tools/run_box_last_bend_experiment.py
```

Отчёты и артефакты:
- `reports/box_last_bend_setups_report.json`
- `reports/diagnostics/box_blocking_poses_reproduction.json`
- Диагностические сцены FreeCAD: `reports/diagnostics/*_scene.FCStd`

## 3. Ключевые геометрические и технологические выводы

1. **Продольные смещения вдоль линии гиба**:
   - Согласно правилу `check_tool_coverage`, инструмент обязан полностью перекрывать линию гиба детали. При длине инструмента, равной длине активного гиба (`match_active_bend_length=True`), любой ненулевой сдвиг $|s| > 0.1$ мм оставляет часть линии гиба незакрытой (`uncovered_left` или `uncovered_right`) и бракуется технологическим оракулом.
   - Увеличение длины инструмента выше длины гиба приводит к ещё более глубокому столкновению с поперечными бортами коробки.

2. **Торцевые коллизии на подводе (B02 и B04)**:
   - В позе подвода $u=0.75$ пуансона AP1017 столкновение объёмом $68.37$ мм³ локализовано строго в торцевых зонах пуансона ($|x| \ge 32.5$ мм). Центральная часть пуансона свободна ($0.0$ мм³).
   - Однако условное снятие торцевой коллизии (`allow_end_zone_collision=True`, 15 мм) не решает проблему полного цикла: при дальнейшем опускании пуансона к $u \approx 0.85$ (перед контактом с листом) стенки коробки клинят по скосу хвостовика пуансона.

3. **Эффект пуансона типа «гусиная шея» (AP1013)**:
   - Использование пуансона с глубоким окном/выемкой `PUNCH_AP_1013_85°_H159,65_R0,8` **полностью устранило блокирующую коллизию на B01 и B03** в фазе гибки: объём пересечения снизился с $442.63$ мм³ до **$0.0001$ мм³** (в пределах численного допуска $10^{-4}$ мм³).
   - При сквозной проверке полной траектории B01 и B03 с AP1013 фазы `APPROACH`, `CONTACT`, `BOTTOM` и `RETRACT` успешно сошлись с нулевым пересечением.
   - В фазе `BENDING` фактических геометрических коллизий также не обнаружено (максимальный зафиксированный объём $0.000009$ мм³ $< 10^{-4}$ мм³), однако адаптивное деление с перестроением B-Rep 8-гибочного тела FreeCAD на 30 итерациях превысило лимит времени 300 с, в силу чего результат строго классифицирован как **UNVERIFIED (timeout)**.

4. **Итог по поиску полной последовательности**:
   - **Допустимый последний гиб в строгом непрерывном режиме без таймаутов не найден** (`CLEAR: 0`, `UNVERIFIED: 2`, `COLLISION: 16`).
   - Полный порядок гибки со стандартным прямым пуансоном AP1017 для данной коробки физически невозможен.
   - Перспективным физическим решением является гиб B01/B03 с оконным пуансоном AP1013 или секционированным инструментом с боковыми разгрузочными пазами (horns/recesses).
